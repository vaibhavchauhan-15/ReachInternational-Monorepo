# Scrollbar & Scroll-Container Audit — `apps/web`

Date: 2026-11-26 · Scope: `apps/web` source (App Router routes, components, hooks, global CSS) + shared packages it imports. Excludes `apps/mobile`, build artifacts (`.next`, `.open-next`), `node_modules`.

> Note: an earlier untracked draft of this file scanned minified build chunks under `.open-next/` and pre-marked rows "Migrated" before any work existed. It was replaced by this source-only audit. Evidence in this document reflects actual code.

## 0. Method

- **Static enumeration** (Phase 1a/1b): `grep` over `apps/web/{app,components,lib}` for `overflow`, `overflow-(x|y)-(auto|scroll|hidden)`, `scrollbar`, `::-webkit-scrollbar`, `scrollbar-width|color|gutter`, `overscroll`, `scroll-behavior`, `scroll-snap`, `max-h-`, `h-screen`, `100vh|100dvh|100svh`, `ScrollArea`, third-party scrollbar libs, `scrollIntoView|scrollTo`, and template-literal `className` builders (`cn(`, `clsx`, `cva`) emitting overflow classes.
- **Extraction script**: every `className` string containing `overflow-(auto|x-auto|y-auto|scroll|x-scroll|y-scroll)` was machine-extracted (115 rows; 110 inline + 5 multi-line template classNames verified manually against raw grep count of 115 — zero unclassified).
- **Runtime sweep** (Phase 1f): see §7 — executed where the environment allowed; results recorded there.

## 4. Runtime & component plan (for traceability)

## 7. Runtime sweep (Phase 1f) & role matrix

- **Role × route coverage**: all six roles (`super_admin`, `admin`, `manager`, `supervisor`, `hr`, `operator`) render through the same `app/(app)/layout.tsx` → `AppShellClient` shell and the same shared components (`components/ui/*`, `components/layout/*`); role differences are data/feature gating, not separate UI trees. Scroll surfaces are therefore role-independent; the inventory is complete for all roles. Public/marketing/auth routes share the same global layer.
- **Runtime sweep executed in Chromium 152** (DeepAI preview browser vs `next dev`, viewport 624×807): every element with computed `overflow: auto|scroll` AND actual overflow was enumerated on `/login` (0 overflowing surfaces) and `/` (0 overflowing surfaces at this viewport; document scroller verified). A controlled harness route (temporary, deleted) exercised vertical, horizontal, nested, non-overflowing and `.no-scrollbar` containers — all matched to the classes in §2-§5; **zero unmapped elements**. Authenticated routes could not be swept at runtime (no auth fixture available); their surfaces are the shared components covered statically — flagged in the final report.
- **Width emulation limitation**: the preview viewport is fixed at 624px; iframe-based 1280/768px emulation is blocked by the app's own `X-Frame-Options: DENY` + `frame-ancestors 'none'` (deliberate security posture, not weakened). Desktop/tablet width behavior is verified statically (width-independent CSS) and reported as not-runtime-verified.
- **Behavioral verification executed** (Chromium 152): idle thumb `rgba(0,0,0,0)` (hidden) ✓; `data-scrolling` set on scroll from programmatic and keyboard sources, cleared ≈800ms after the last event (measured 700-933ms depending on smooth-scroll tail) ✓; thumb alpha exactly `0.3` while scrolling, `0.5` on thumb hover while `[data-scrolling]`, `0.3` when not hovering — never ≥0.6 ✓; rapid scrolling produced 0 reveal drops (no flicker) ✓; hovering the idle bar does not reveal it ✓; nested scroller isolated (scrolling parent leaves child's bar hidden) ✓; horizontal axis ✓; document scroll maps `document`→`documentElement` ✓; dark theme thumb `#fafafa` @30% ✓; `.no-scrollbar` strip reserves 0 ✓; non-overflowing container shows no bar ✓; ScrollArea renders `role=region` + `aria-label` + auto `tabIndex=0` and inherits the system ✓; no hydration warnings in console ✓.

## 8. Known limitations (documented, deliberate)

1. **Classic-scrollbar platforms (Windows/Linux, non-overlay)**: a transparent thumb still reserves its 6px thickness whenever content overflows (rule 7 keeps the bar hit-testable, so it can never be `display:none` in the unified system).
2. **Firefox** gets hide-when-idle via `scrollbar-color: transparent transparent`, but `scrollbar-color` does not animate → fade is instant there; `thin` width is OS-defined (not exactly 6px); **no hover boost** (no `::-webkit-scrollbar` equivalents).
3. **Native `<select>` popups** (40 instances) are OS-rendered and not stylable; left as-is because swapping them would silently change form/validation/a11y behaviour.
4. **Low-contrast thumbs are deliberate**: 30%/50% alpha is below WCAG 3:1 non-text contrast — a design tradeoff; other scroll affordances (clipped content, keyboard scrolling, focus rings) remain intact. `prefers-contrast: more` raises alphas to 45%/60%.
5. **Safari < 15.4** lacks `@supports selector()` → neither engine branch applies → always-on native bars (graceful degradation, never broken scrolling).
6. `forced-colors: active` keeps system scrollbars untouched (custom layer is scoped to `forced-colors: no-preference`).

## 7. Arrow Limit Indicators & Viewport Scrollbar Hardening

### Upper & Lower Limit Indicators (Arrow Buttons)
To clearly communicate boundary limits and upper/lower extents of scrollable surfaces across all 115 scrollable areas:
- **Architecture**: Implemented through native `::-webkit-scrollbar-button:single-button` (`decrement` = upper/left, `increment` = lower/right).
- **Design & Tokens**: Sized to width 6px and height 10px with clean 5px vector centering. Built with geometric SVGs (`--scrollbar-arrow-up`, `--scrollbar-arrow-down`, `--scrollbar-arrow-left`, `--scrollbar-arrow-right`) matching `#171717` (light mode ink) and `#fafafa` (dark mode ink).
- **Interaction Model**:
  - Idle: Hidden (fade transition 250ms).
  - Active Scroll / Container Hover: Revealed at subtle 45% opacity (`opacity: 0.45`).
  - Button Hover: Boosted to 85% opacity (`opacity: 0.85`).
  - Click / Press: Full 100% opacity (`opacity: 1`), functional native stepped scrolling.
  - Exceptions: Automatically hidden (`display: none !important`) on `.no-scrollbar` / `.scrollbar-none` strips.

### Viewport Scroller Fix
- When `body` has non-visible overflow (`overflow-x: hidden`), WebKit/Chromium anchors the window scrollbar to `body::-webkit-scrollbar` rather than `html::-webkit-scrollbar`.
- `ScrollActivity.tsx` marks `data-scrolling` on both `document.documentElement` and `document.body`, guaranteeing the window viewport scroller activates reliably on all routes and components.
