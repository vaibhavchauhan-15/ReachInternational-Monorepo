### Boundary Enforcement Rules:
- ❌ **Forbidden**: `packages/*` → `apps/*` (Packages MUST NOT import from applications).
- ❌ **Forbidden**: `foundation packages` → `shared/domain packages` (No upward dependencies).
- ❌ **Forbidden**: `apps/web` ↔ `apps/mobile` (No cross-app imports).
- ❌ **Forbidden**: Circular workspace dependencies (Direct or indirect).
- ❌ **Forbidden**: Deep internal imports (Always import strictly through canonical package export barrels `index.ts`).
- ✅ **Allowed**: `apps/*` → Shared domain & foundation packages.
- ✅ **Allowed**: Shared domain packages → Foundation packages (`types`, `utils`).

## 3. Web Architecture Policy (`apps/web`)

1. **Server Components First (RSC)**:
   - All pages in `app/(app)/` default to React Server Components.
   - Initial page loads fetch data server-side via `lib/dal.ts` or `lib/queries/*`.
   - Client components (`'use client'`) must be leaf nodes.
2. **Data Access Layer (DAL)**:
   - Direct database access is restricted to `lib/dal.ts` and `lib/queries/*`.
   - Never use `SELECT *`; always specify explicit columns.
   - Authenticated Supabase clients are created per-request via `@supabase/ssr` cookies.
3. **Server Actions for Mutations**:
   - All database writes go through `app/actions/*`.
   - Mutations MUST authenticate the session, check permissions via `@reachinternational/permissions`, validate with Zod via `@reachinternational/validation`, log mutations to `audit_logs`, and call `revalidateTag` / `revalidatePath`.
4. **Shell & Responsive Layout**:
   - Desktop uses collapsible `AppSidebar` (256px expanded / 64px collapsed).
   - Mobile uses `MobilePageHeader` and floating `BottomNav`.

## 4. Native Mobile Architecture Policy (`apps/mobile`)

1. **Framework & Navigation**:
   - Built on **Expo SDK 57 (React Native 0.86)** with **Expo Router**.
   - Route hierarchy mirrors Web App Router 1-to-1 (`app/(app)/*`).
2. **Native Data Layer & TanStack Query**:
   - Server state caching and invalidation are managed via **TanStack Query** (`@tanstack/react-query`).
   - Default query stale time is 30 seconds.
   - List screens implement pull-to-refresh (`RefreshControl`).
3. **Hardware-Backed Auth Persistence**:
   - Tokens are stored securely using `expo-secure-store` backed by Android KeyStore and iOS Keychain.
4. **Offline-First Synchronization**:
   - Proactive network monitoring via `@react-native-community/netinfo`.
   - Offline mutations queue in `AsyncStorage`.
   - Contextual `OfflineBanner` informs users of local storage and auto-sync on reconnect.
5. **Touch & Motion Primitives**:
   - Minimum 44px touch targets on all interactive elements.
   - React Native Reanimated spring physics for segmented controls and cards.
   - Haptic feedback via `expo-haptics` (`Haptics.selectionAsync()`).

## 5. Canonical User Roles (Strictly 6 Roles Monorepo-Wide)

ReachInternational operates strictly under **6 canonical roles**:

1. **`super_admin`**: Full platform control, tenant isolation, security enforcement, global oversight.
2. **`admin`**: Global organizational management, user administration, fleet and client management.
3. **`manager`**: Operational review, shift review, equipment allocation, payroll approval.
4. **`supervisor`**: Site-level coordination, equipment supervision, direct operator assignment management.
5. **`hr`**: Human resources, personnel lifecycle, profile change requests, user records.
6. **`operator`**: Daily machine operation, HMR meter logging (`/operations?tab=entry`), shift execution.

AI agents MUST NOT invent or resurrect legacy roles.

## 7. Web & Native Architecture Parity Contract

Web and Native Mobile are two interfaces for **one single product**:
- Business rules, validation schemas, permissions, data models, error semantics, and status flows MUST remain 100% identical.
- UI presentation adapts to the platform (tables on desktop web vs. touch cards on mobile), while maintaining the exact same color, typography, icons, and visual language.
