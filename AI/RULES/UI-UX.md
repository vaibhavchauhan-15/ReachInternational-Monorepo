# ReachInternational Production UI/UX Engineering Rules & Policy

> **AUTHORITATIVE UI/UX ENGINEERING POLICY FOR AI AGENTS**  
> *This document establishes the binding user interface, interaction design, and user experience engineering policy for all web (`apps/web`) and mobile (`apps/mobile`) applications within the ReachInternational monorepo. Every AI coding agent MUST read, obey, and enforce these rules before creating or modifying any page layout, form interaction, data table, modal dialog, navigation flow, or state feedback component in this repository.*

---

## MANDATORY AGENT RULE: WEB-TO-MOBILE CHANGE SYNCHRONIZATION

> **CRITICAL MANDATE FOR ALL AI AGENTS**:
> Whenever ANY change, feature, component, style, theme, color, modal, drawer, page, module, form field, status badge, navigation item, database/API hook, or workflow is added, modified, refactored, or fixed in the **Web App (`apps/web`)**, the AI agent **MUST MANDATORILY apply and synchronize the exact same change in the Mobile App (`apps/mobile`)** with full mobile compatibility (touch cards, bottom sheets, min 44px touch targets) in the same session/task.

---

## 1. Purpose

The purpose of ReachInternational's UI/UX engineering policy is to build an **industrial-grade, low-friction, high-density, error-resistant operational platform** for Service Managers, Field Engineers, Mechanics, Supervisors, Operators, Store Managers, HR Managers, Rental Managers, Sales Executives, Finance Managers, and Admins.

Every interface generated by an AI agent MUST be:
* **Efficient**: Minimizes clicks, typing, and unnecessary navigation for daily repetitive operations.
* **Predictable**: Reuses canonical interaction patterns across all 26 domain modules without surprising the user.
* **Safe**: Protects against accidental data loss, unvalidated inputs, and destructive single-click actions.
* **Accessible & Responsive**: Fully usable across Mobile (≤640px touch cards), Tablet (641px–1023px 2-col grids), and Desktop (≥1024px high-density tables).
* **Visually Compliant**: Strictly follows the Vercel Geist design system documented in `DESIGN.md` and `AI/RULES/DESIGN-SYSTEM.md`.

---

## 2. UX Principles

1. **Operational Efficiency > Decorative UI**: ReachInternational is an operational enterprise tool, not a marketing site. Interfaces MUST prioritize fast data entry, quick scanning, and high operational throughput over decorative white space.
2. **Scannable Density**: Information density MUST remain scannable via clear visual hierarchy, consistent grouping, and alignment.
3. **Explicit Primary Action**: Every major screen MUST feature one obvious primary action when actions are available.
4. **Single-Scroll Container Standard**: Every view and modal body MUST enforce exactly one primary scroll container (`flex-1 overflow-y-auto min-h-0`).
5. **Proactive Error Prevention**: UI MUST prevent impossible states, validate inputs in real-time, and protect against data loss.
6. **Immediate System Feedback**: Every mutation action MUST produce instant feedback via toasts, spinners, and state updates.

---

## 3. Design System Relationship

1. **`DESIGN.md` & `AI/RULES/DESIGN-SYSTEM.md` Primary Authority**: Visual styling (colors, typography, border radius, spacing, elevation) MUST strictly follow `DESIGN.md` and `AI/RULES/DESIGN-SYSTEM.md`. No UI/UX rule shall be interpreted as permission to introduce non-tokenized hex colors or arbitrary visual styling.
2. **Interaction vs Visual Distinction**:
   * *Design System Concern*: Button fill color (`#171717`), corner radius (`6px`), font size (`14px`).
   * *UI/UX Concern*: Whether the button should exist, its priority placement on the screen, its loading/disabled state, the feedback modal after click, and keyboard accessibility.

---

## 4. User Goals

Every screen in ReachInternational MUST have a single, obvious primary purpose. Before modifying or creating a page, AI agents MUST establish:

1. **Primary Goal**: What is the user trying to accomplish here? (e.g. Log a Breakdown Complaint, Submit Daily Machine Meter, Approve Purchase Order).
2. **Primary Action**: Prominent CTA button placed top-right or in header (`+ Create Complaint`, `Submit Daily Log →`).
3. **Primary Content**: High-density data table or task list answering the primary goal.
4. **Secondary Actions**: Export CSV, Filter, Reset, Print A4 FSR.
5. **Contextual Actions**: Row-level edit/view icons wrapped with `<TooltipWrapper>`.

## 6. Navigation

1. **Web AppSidebar**: Left collapsible navigation shell displaying logo, domain links, and active route highlight (`#171717` ink fill with white icon/text).
2. **AppHeader Controls**: Top bar housing Page Title/Breadcrumbs, `<BranchSelector />` (global vs branch-scoped view switcher), `<CommandPalette />` trigger (`Ctrl+K`), `<ThemeToggle />`, notification bell with unread badge counter, and user profile menu.
3. **Mobile Navigation**: Hamburger menu opening slide-over drawer modal + `MobileBottomNav` for instant tab switching.

---

## 7. Page Structure

Every operational page MUST follow a consistent 5-zone vertical composition:

```text
Zone 1: PageHeader        → Title, Subtitle, Eyebrow, Primary Action CTA button
Zone 2: Metric Cards      → 4-card KPI summary strip (MetricCard component)
Zone 3: FilterToolbar     → Real-time Search Input + Date Range Pills + Status Filter Pills
Zone 4: Primary Data      → EnterpriseTable (hidden sm:block) / Touch Card View (block sm:hidden)
Zone 5: Pagination & Meta → Record Counter ("Showing 1-25 of 142 records") + Pagination Bar
```

---

## 8. Information Hierarchy

AI agents MUST organize page elements according to strict visual hierarchy:

```text
Level 1 (Highest): Page Title & Primary CTA Button (+ Create Machine, Submit Log →)
Level 2:           KPI Metric Numbers & Primary Status Badges (🔴 Breakdown / 🟢 Approved)
Level 3:           Table Data Cells, Machine Codes (#MCH-001), Customer Names
Level 4:           Filter Toolbar Pills, Date Timestamps, Secondary Metadata
Level 5 (Lowest):  Captions, Tooltips (<TooltipWrapper>), Helper Subtitles
```

**Rule**: Level 1 elements MUST dominate visually via weight 600 typography and `#171717` ink styling. Equal visual weight MUST NOT be given to all elements.

---

## 9. Action Hierarchy

Actions MUST use standardized visual styling based on priority:

```text
ACTION LEVEL       STYLING / TAILWIND CLASS                          EXAMPLE
──────────────────────────────────────────────────────────────────────────────────────────
1. Primary Action   → bg-[#171717] text-white rounded-sm px-4 py-2    "+ Add Machine", "Submit Log →"
2. Secondary Action → border border-[#ebebeb] bg-white text-[#171717] "Export CSV", "Reset Filters"
3. Tertiary Action  → Icon-only button with <TooltipWrapper>       <Edit />, <Eye />, <Trash2 />
4. Destructive Action→ bg-red-600 text-white rounded-sm + Modal   "Delete Machine", "Reject FSR"
```

1. **One Primary Action Per View**: A view MUST NOT contain multiple competing primary black buttons.
2. **Icon Button Tooltips**: Desktop icon-only action buttons MUST be wrapped with `<TooltipWrapper content="...">`.

## 10. Search

1. **Global Search (`CommandPalette.tsx`)**: Triggered via `Ctrl+K` or clicking search trigger in `AppHeader`. Searches routes, machines, complaints, customers, and employees across the system.
2. **Module Table Search**: Integrated inside `FilterToolbar`. Real-time filtering matching code, name, model, serial number, or remarks.
3. **Preserve Query**: Clearing search input MUST instantly restore full dataset without full page reload.

---

## 11. Filters

Filters MUST use the canonical `FilterToolbar` component pattern:

```tsx
<div className="flex flex-col sm:flex-row items-stretch sm:items-center justify-between gap-3 bg-white p-3 border border-[#ebebeb] rounded-md">
  <div className="flex items-center gap-2 overflow-x-auto custom-scrollbar flex-nowrap">
    <SearchInput value={search} onChange={setSearch} placeholder="Search records..." />
    <FilterPills options={statusOptions} active={activeStatus} onChange={setActiveStatus} />
  </div>
  <div className="flex items-center gap-2">
    <DatePeriodSelector value={period} onChange={setPeriod} />
    {hasActiveFilters && <Button variant="ghost" onClick={resetFilters}>Clear Filters</Button>}
  </div>
</div>
```

* **Active Filter Visibility**: Active status and date filter pills MUST highlight with `#171717` ink fill.
* **1-Click Reset**: When filters are active, a `Clear Filters` button MUST appear.
* **Mobile Scroll Strip**: Filter pill containers MUST use `overflow-x-auto flex-nowrap` on mobile viewports.

## 12. Tables

Data tables handle large-scale fleet, financial, and inventory data. AI agents MUST use `EnterpriseTable.tsx`:

```text
ENTERPRISE TABLE SPECIFICATIONS

• Header Row:       Geist Mono (font-mono text-xs uppercase tracking-wider text-[#8f8f8f])
• Cell Typography:  Geist Sans (text-sm text-[#171717])
```

## 13. Cards

1. **Metric Cards (`MetricCard.tsx`)**: Displays KPI summary count, label (uppercase Geist Mono), trend badge, and icon. Arranged in 4-column grid on desktop (`grid-cols-4`), 2-column on tablet (`grid-cols-2`), single-column on mobile.
2. **Feature Cards (`feature-card`)**: White card surface (`#ffffff`) with 1px hairline border (`#ebebeb`) and 12px radius (`rounded-md`).
3. **Mobile Touch Cards**: Card view replacement for data tables on viewports ≤640px (`block sm:hidden`).

---

## 14. Forms

Forms MUST optimize operational data entry for speed and accuracy:

1. **4-Section Logical Grouping**:
   * *Section A (Identity & Primary Context)*: Machine Code, Customer Name, Branch.
   * *Section B (Operating Metrics)*: Hour Meters, Shift Times, Fuel Logs.
   * *Section C (Status & Breakdown)*: Progressive disclosure card expanding breakdown reason/duration only if status === 'breakdown'.
   * *Section D (Remarks & Attachments)*: Quick tag shortcuts (`+ Fuel Refill`, `+ Maintenance Attended`) & file uploader.
2. **Auto-Fill & Locked Fields**: Selecting a primary dropdown item MUST populate and lock read-only fields.
3. **Auto-Calculation**: Inputting start/end times MUST auto-calculate operating duration and overtime.
4. **Custom Time Picker (`CustomTimePicker.tsx`)**: Time fields MUST use radial circular clock face with IST GMT+5:30 precision.
5. **Sticky Action Footer**: Submit controls MUST remain pinned to bottom of container.

---

## 15. Modals / Drawers / Sheets

AI agents MUST select dialog containers based on interaction complexity:

```text
CONTAINER TYPE     USE CASE                                TAILWIND CLASS / SPEC
──────────────────────────────────────────────────────────────────────────────────────────
• Modal Dialog    Short focused forms, confirmations     w-full max-w-lg bg-white shadow-lg
• Fluid Sheet     Contextual detail view while retaining  w-full sm:max-w-xl md:max-w-2xl
                  underlying page state
```

### Mobile Clamping Rule:
Modals rendered on mobile MUST enforce height clamping and internal scroll:
```tsx
className="w-full max-h-[calc(100vh-2rem)] overflow-y-auto rounded-lg p-4 sm:p-6"
```

## 16. Detail Views

1. **Machine Detail (`/machines/[id]`)**: Extended technical specs, Insurance/RTO compliance cards, service logbook, and active operator assignments.
2. **Service & FSR Detail (`/service`)**: Digital FSR inspection checklist, replacement parts ledger, and 1-click A4 PDF print launcher.
3. **Context Preservation**: Saving changes inside a detail modal/drawer MUST update underlying list view state seamlessly without full page redirects.

## 17. Dashboards

1. **`/dashboard` Operator Portal**: Supports tabbed URL switching (`/dashboard?tab=entry` for Daily Machine Log form vs `/dashboard?tab=history` for Submitted Log History).
2. **`/my-work` Action Center**: Personalized workload hub querying live assigned items (`assigned_machines`, `assigned_jobs`, `machine_complaints`, `purchase_orders` requiring approval). Provides clean empty state ("No Assigned Tasks Today") for field staff with zero pending items.

---

## 18. Tabs

1. **Tab Switchers**: Category tab switchers use 64px radius pills (`rounded-[64px]`). Active tab highlights with `#171717` ink fill and white text.
2. **URL State Synchronization**: Tab selection MUST synchronize with URL search params (e.g. `?tab=entry` vs `?tab=history` or `/service?tab=complaints`) to support direct bookmarking and edge navigation.

## 19. Status & Feedback

Status communications MUST be readable at a glance:

```text
STATUS TIER     BADGE STYLING                                  EXAMPLE USAGE
──────────────────────────────────────────────────────────────────────────────────────────
• Approved      bg-emerald-50 text-emerald-700 border-emerald-200  Log Stored & Approved
• Breakdown     bg-red-50 text-red-700 border-red-200              🔴 Machine Breakdown
• Pending       bg-amber-50 text-amber-700 border-amber-200        Pending PO Approval
```

### Toast Feedback Mandate:
Mutations MUST trigger instant toast alerts: `toast.success("Daily machine log stored & approved")` or `toast.error("Failed to update status")`.

---

## 20. Loading States

1. **Loading Skeletons**: Content-heavy tables and metric cards MUST display pulse skeletons (`<Skeleton />`) during data fetching to prevent visual layout shifts.
2. **Action Loading States**: Submit buttons MUST display an animated spinner (`<Spinner />`) and set `disabled={loading}` during server action mutations.

---

## 21. Empty States

List and data views MUST provide meaningful empty state feedback:
* **Initial Empty State**: "No machines registered yet" + `+ Add Machine` CTA.
* **Filter Empty State**: "No records match your active search filters" + `Reset Filters` CTA button.

---

## 22. Error States

1. **Field-Level Errors**: Forms MUST render red error text (`text-red-600 text-xs mt-1`) beneath the specific invalid input.
2. **Server Errors**: Failed server action mutations MUST return structured error payloads caught and displayed in an inline alert card (`<Alert variant="destructive">`).
3. **Recovery Triggers**: Error cards MUST provide an explicit `Retry` or `Go Back` action button.

---

## 23. Destructive Actions

Direct single-click destructive operations (Delete Machine, Terminate Agreement, Reject FSR) are **STRICTLY FORBIDDEN**.

1. **Red Action Styling**: Destructive buttons MUST use red styling (`bg-red-600 text-white` or `text-red-600`).
2. **Confirmation Modal**: Destructive clicks MUST trigger a confirmation dialog modal (`<ConfirmationDialog />`).
3. **Clear Labels**: Confirmation buttons MUST use explicit labels (`Yes, Delete Machine`).

---

## 24. Bulk Operations

When `<EnterpriseTable>` selection is active:

1. **Selection Counter**: Floating bar appears displaying `X records selected`.
2. **Bulk Action Buttons**: Primary bulk operations (e.g. `Export Selected CSV`, `Batch Assign Engineer`).
3. **Bulk Destructive Guard**: Executing bulk delete MUST trigger confirmation dialog displaying exact item count (`Are you sure you want to delete 12 selected records?`).

---

## 25. File Uploads

1. **FSR A4 PDF Engine**: Digital Field Service Reports include 1-click A4 PDF print launcher (`210mm x 297mm`) stripping browser header/footers.
2. **Directory CSV Export**: Machine and Inventory directories include 1-click `Export CSV` extracting active dataset with complete column metadata.
3. **File Uploaders**: Drag-and-drop file uploaders MUST specify accepted extensions (`.pdf, .png, .jpg`), max file size (e.g. `10MB`), upload progress spinner, and preview thumbnail.

---

## 26. Data Entry

Because ReachInternational is an operational platform, AI agents MUST optimize repetitive data entry:
* Provide smart defaults where possible.
* Use searchable select popovers (`SearchableSelect.tsx`) for long option lists.
* Auto-calculate durations and overtime.
* Support keyboard navigation (`Tab` focus order, `Enter` submission).

---

## 27. Workflow UX

AI agents MUST preserve complete end-to-end operational workflows:
* **Service Workflow**: Complaint Logged → Assigned → FSR Completed → Manager Review → Resolution.
* **Rental Workflow**: Request → Agreement (>15% discount check) → Delivery Challan → Return Inspection → Damage Routing.
* **Finance Workflow**: PO Created → GRN Verified → Supplier Invoice Matched (3-Way) → Ledger Payment.

---

## 28. Role-Specific UX

ReachInternational enforces Role-Based Access Control across 13 enterprise roles:

1. **UI Permission Gating**: AI agents MUST wrap privileged UI controls with `roleHasPermission(user.role, permissionCode)` or DAL permission checks.
2. **Branch Scoping**: `<BranchSelector />` in `AppHeader` scopes queries globally or to user's assigned branch (`DEL-HQ`).
3. **Field Staff Simplicity**: Field Engineers, Mechanics, and Operators MUST be presented with streamlined, high-density interfaces (`/my-work`, `/dashboard?tab=entry`) free of administrative noise.

---

## 29. Mobile UX (≤640px)

* High-density tables reflow into Touch Cards (`block sm:hidden`).
* Filter pill strips scroll horizontally (`overflow-x-auto flex-nowrap`).
* Modal dialogs clamp to viewport height (`max-h-[calc(100vh-2rem)] overflow-y-auto`).
* Interactive touch targets clear min 44px hit area.

---

## 30. Tablet UX (641px–1023px)

* Form field rows and metric cards reflow into 2-column grids (`grid-cols-1 sm:grid-cols-2`).
* Modals scale fluidly (`sm:max-w-xl md:max-w-2xl`).
* Secondary action buttons collapse into icon-only controls.

---

## 31. Desktop UX (≥1024px)

* Full 3-column or 4-column layout (`grid-cols-3` / `grid-cols-4`).
* High-density `<EnterpriseTable>` with sorting, column visibility, and density controls.
* Icon-only action buttons wrapped with `<TooltipWrapper>`.

---

## 32. Accessibility UX

1. **WCAG 2.2 AAA Target**: Text contrast meets WCAG ratios (`#171717` ink on `#fafafa` canvas).
2. **Visible Focus Rings**: Interactive controls display visible blue focus rings (`ring-2 ring-[var(--color-link)]`).
3. **Non-Color Status Signals**: Status indicators MUST pair color badges with text labels or status icons.

---

## 33. Performance UX

1. **Zero Layout Shifts**: Skeletons match exact content height before data loads.
2. **Immediate Feedback**: Submit buttons enter loading state instantly upon click to prevent duplicate submissions.

---

## 34. Cross-Module Consistency

All 26 operational modules MUST use identical interaction patterns for Search, Filter, Table, Form, Modal, Status Badges, and Error Handling. Users MUST NOT be forced to learn different UI paradigms across modules.

---

## 35. UX Anti-Patterns (NEVER INTRODUCE)

AI agents MUST NEVER introduce any of the following UX anti-patterns:
* ❌ **Single-Click Destructive Actions**: Deleting records without confirmation modal.
* ❌ **Duplicate Submit Triggers**: Leaving submit buttons active during pending mutations allowing double-clicks.
* ❌ **Ambiguous Error Toasts**: Displaying generic `An error occurred` without explaining the root cause.
* ❌ **Un-Resetable Filter Toolbars**: Providing active filter options without a 1-click `Clear Filters` CTA.
* ❌ **Nested Double Scrollbars**: Creating inner scroll containers inside form bodies that create double scrollbars.
* ❌ **Desktop Tables on Mobile**: Rendering dense multi-column data tables on mobile without touch card reflow (`block sm:hidden`).
* ❌ **Un-Tooltiped Icon Buttons**: Desktop icon-only action buttons rendered without `<TooltipWrapper>` hover labels.

---

## 36. UX Change Policy

AI agents MUST NOT refactor, redesign, or alter existing UX interaction patterns unless explicitly commanded by the user. `DESIGN.md` and `AI/RULES/UI-UX.md` remain the binding authority.

---

## 37. UX Regression Protection

Before modifying a shared UI primitive in `apps/web/components/ui/` or `components/layout/`:
1. Audit downstream impact across all 26 domain modules.
2. Verify cross-platform parity between Web (`apps/web`) and Mobile (`apps/mobile`).
3. Verify zero compilation errors across all workspace packages (`pnpm typecheck`).

---

## 38. AI Agent Pre-Implementation Checklist

Before writing any user interface, form, table, or layout code, every AI agent MUST complete this mental checklist:

* [ ] Have I identified the primary goal and primary action CTA of this view?
* [ ] Does the page follow the standard 5-zone vertical composition (Header → Metrics → Filters → Data Table → Pagination)?
* [ ] Are buttons using canonical action hierarchy (Primary black `button-primary-sm` vs Secondary white `button-ghost-sm` vs Icon `<TooltipWrapper>`)?
* [ ] Are form inputs grouped into 4 logical sections with auto-fill, auto-calculation, and IST `CustomTimePicker` controls?
* [ ] Is mobile touch card reflow implemented (`block sm:hidden`) for viewports ≤640px?
* [ ] Are interactive touch targets ≥44px on mobile?
* [ ] Do destructive actions require an explicit confirmation modal dialog?
* [ ] Are loading skeletons and action submit spinners present to prevent duplicate requests?

---

## 39. AI Agent Post-Implementation UX Audit

After completing code modifications, every AI agent MUST perform the following verification protocol:

1. **UX Workflow Audit**: Verify primary user workflow is low-friction and error-free.
2. **Responsive Viewport Audit**: Test layout across Mobile (≤640px), Tablet (641px–1023px), and Desktop (≥1024px).
3. **Theme & Design Audit**: Verify strict compliance with `DESIGN.md`, `AI/RULES/DESIGN-SYSTEM.md`, and `AI/RULES/UI-UX.md`.
4. **Compilation Verification**: Run `pnpm typecheck` across all monorepo workspace packages.
5. **Memory Synchronization**: Update `AI/STATE.md`, `AI/CURRENT_TASK.md`, `AI/CHANGELOG_AI.md`, and `README.md`.
