# ReachInternational Production Design System Rules & Policy

> **AUTHORITATIVE DESIGN-SYSTEM ENFORCEMENT POLICY FOR AI AGENTS**  
> *This document establishes the binding visual design and UI component policy for all web (`apps/web`) and mobile (`apps/mobile`) development within the ReachInternational monorepo. Every AI coding agent MUST read, obey, and enforce these rules before creating or editing any user interface component, page layout, or styling code in this repository.*

---

## 1. Purpose

The purpose of this document is to guarantee total visual consistency, prevent design system fragmentation, protect brand identity, enforce responsive cross-platform layout standards, and eliminate arbitrary one-off UI implementations across ReachInternational.

AI agents MUST treat this document as an **executable design policy**. Any code generated by an AI agent that violates the visual specifications, color tokens, typography scales, border radii, or layout rules documented herein is considered defective and non-compliant.

---

## 2. Authoritative Source of Truth — `DESIGN.md`

The project file:

```text
DESIGN.md
```

located at the workspace root is the **PRIMARY AND AUTHORITATIVE SOURCE OF TRUTH FOR THE VISUAL DESIGN OF THE APPLICATION**.

### Core Authority Invariants:
1. **`DESIGN.md` Overrides Agent Preference**: Future AI agents MUST NOT invent custom visual styles, redesign components based on personal aesthetic taste, or introduce alternative design systems (e.g. standard Tailwind defaults, Material UI, Bootstrap, or arbitrary hex colors).
2. **`DESIGN.md` Overrides Accidental Implementation Deviations**: If an existing component or page in the codebase deviates from `DESIGN.md`, `DESIGN.md` remains authoritative. AI agents MUST NOT use an existing non-compliant component as justification to propagate invalid design patterns.
3. **No Unintended Design Modifications**: AI agents MUST NOT alter global CSS variables in `apps/web/app/globals.css`, change tokens in `packages/design-tokens`, or edit `DESIGN.md` unless explicitly commanded by the user.

## 3. Design Philosophy — The Vercel Geist System

ReachInternational's visual identity is built on the **Vercel Geist System** — an exercise in intentional subtraction, creating a stark, high-density, black-on-near-white developer-and-enterprise platform aesthetic.

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│                             VERCEL GEIST PHILOSOPHY                              │
├──────────────────────────────────────────────────────────────────────────────────┤
│ • Ink & Canvas Duet: Single ink tone (#171717) carries headings, CTAs & borders. │
│ • Near-Zero Chromatic Chrome: Color is strictly restricted to semantic status    │
│   signals and the single multi-stop mesh gradient confined to hero sections.     │
│ • Bimodal Button Radii: 100px full pills for marketing CTAs vs. 6px tight        │
│   squares for functional app & nav controls.                                     │
│ • Display Typography: Geist Sans with tight negative letter-spacing (-2.4px).    │
│ • Technical Eyebrows: Geist Mono uppercase section labels (12px, weight 500).   │
│ • Crisp Hairline Surfaces: 1px border (#ebebeb) on white cards (#ffffff).       │
└──────────────────────────────────────────────────────────────────────────────────┘
```

---

## 4. Brand Identity & Visual Language

* **Near-Zero Chromatic Chrome**: The interface relies almost exclusively on a near-black ink tone (`#171717`) set against a near-white background canvas (`#fafafa`). Large surfaces MUST NOT be filled with bright chromatic colors.
* **Hero Mesh Gradient**: The sole decorative flourish allowed on the platform is a multi-stop mesh gradient (cyan `#50e3c2`, blue `#0070f3`, violet `#7928ca`, magenta `#eb367f`, pink `#ff0080`, amber `#f9cb28`) confined strictly to hero sections and brand illustration bands.
* **Technical Precision**: The page layout reads like clean, engineered documentation — precise grids, hairline borders, compact data density, and clear typographic hierarchy.

## 6. Semantic Colors

Semantic colors communicate operational status across all modules (Machines, Complaints, FSRs, Inventory, Finance, Tasks). AI agents MUST enforce uniform semantic color application:

* **Success / Operational**: `#10b981` (`var(--color-success)` / `colors.success`). Deep: `#059669`. Soft background: `#ecfdf5`.
* **Information**: `#3b82f6` (`var(--color-info)` / `colors.info`). Soft background: `#eff6ff`.

**Rule**: AI agents MUST NOT invent module-specific status colors (e.g. green A for HR vs green B for Finance). The semantic token scale is universal across all 26 modules.

## 7. Typography Hierarchy

The system operates strictly on **Geist Sans** (for display and body UI) and **Geist Mono** (for code, machine numbers, serial tags, and technical eyebrows).

```text
DESIGN.MD REQUIREMENT              CSS TOKEN                     TYPOGRAPHIC PROPERTIES
──────────────────────────────────────────────────────────────────────────────────────────────────────────
display-xl  (Hero Headline)     → --text-display-xl-size     48px / weight 600 / line 48px / tracking -2.4px
heading-lg  (Section Header)    → --text-heading-lg-size     32px / weight 600 / line 40px / tracking -1.28px
heading-md  (Card/Modal Title)  → --text-heading-md-size     20px / weight 600 / line 28px / tracking -0.4px
label-sm    (Button/Form Label) → --text-label-sm-size      14px / weight 500 / line 20px / tracking -0.28px
mono-eyebrow(Technical Eyebrow) → --text-mono-eyebrow-size   12px / Geist Mono 500 / line 16px / UPPERCASE
body-lg     (Lead Prose)        → --text-body-lg-size        16px / weight 400 / line 24px / tracking 0
body-md     (Default Body/Cell) → --text-body-md-size        14px / weight 400 / line 20px / tracking 0
body-sm     (Caption/Metadata)  → --text-body-sm-size        12px / weight 400 / line 16px / tracking 0
code        (Code/Machine Code) → --text-code-size           14px / Geist Mono 400 / line 20px
```

### Typography Rules:
1. **Tight Negative Display Tracking**: The larger the heading, the tighter the negative letter-spacing (-2.4px at 48px, -1.28px at 32px, -0.4px at 20px). Body copy sits at neutral spacing.
2. **Binary Font Weights**: Weights are binary: `600` for headings, `500` for buttons and labels, `400` for body copy. Light (300) or Extra Bold (800/900) weights are **FORBIDDEN**.
3. **Geist Mono Role Scoping**: Geist Mono (`font-mono`) MUST be used ONLY for code, machine identifiers (`#MCH-001`), serial numbers, table column headers, and uppercase section eyebrows. It MUST NOT be used for standard body copy.

## 8. Spacing System

Spacing is based on a strict **4px base unit** scale:

```text
xxs: 4px   │ xs: 8px    │ sm: 12px   │ md: 16px   │ lg: 24px
xl:  32px  │ 2xl: 40px  │ 3xl: 64px  │ 4xl: 96px  │ section: 128px
```

### Spacing Rules:
* **Card Interior Padding**: MUST use `p-4` (16px), `p-6` (24px), or `p-8` (32px).
* **Section Gap Padding**: MUST use `space-y-6` (24px) or `space-y-8` (32px).
* **No Arbitrary Padding**: Hardcoded non-standard pixel margins/paddings (e.g. `margin: 13px`, `padding: 19px`, `gap: 27px`) are **STRICTLY FORBIDDEN**.

## 9. Border Radius System — Bimodal Language

ReachInternational uses a **bimodal border radius system** to signal functional context:

```text
           BIMODAL BORDER RADIUS SYSTEM
┌─────────────────────────────────────────────────┐
│  APP & NAV CONTROLS: Tight 6px Square (rounded-sm)│
│  MARKETING CTAs:    100px Full Pill (rounded-pill)│
└─────────────────────────────────────────────────┘
```

| Radius Token | Value | Tailwind Class | Designated UI Component Usage |
| :--- | :--- | :--- | :--- |
| `none` | 0px | `rounded-none` | Full-bleed section bands, dividers |
| `sm` | 6px | `rounded-sm` | Nav buttons, app CTAs, text inputs, selects, dropdown items, table badges |
| `md` | 12px | `rounded-md` | Feature cards, form containers, dialog cards, code blocks |
| `lg` | 16px | `rounded-lg` | Large modal panels, pricing cards, drawer containers |
| `pill-category` | 64px | `rounded-full` / `rounded-[64px]` | Category filter tabs (`Log Entry` vs `Log History`) |
| `pill` | 100px | `rounded-full` | Marketing CTA buttons ("Start Deploying", "Get a Demo") |
| `full` | 9999px | `rounded-full` | Circular icon buttons, user avatars, status dot indicators |

**Rule**: AI agents MUST NOT mix radius languages. Application operational controls (buttons, inputs, tables) MUST use tight 6px corners (`rounded-sm`). Marketing pill buttons (`rounded-full`) MUST NOT be used inside dense enterprise data tables or form rows.

## 10. Elevation & Depth System

Depth is deliberately minimal. The system prefers crisp 1px hairline borders to heavy drop shadows.

* **Level 0 (Flat — Default)**: 1px hairline (`border border-[var(--color-hairline)]`), zero shadow. Used for default feature cards, table cells, form field inputs, dividers.
* **Level 1 (Whisper)**: 1px hairline + micro shadow (`shadow-[0px_1px_2px_rgba(0,0,0,0.04)]`). Used for lightly raised cards on hover.
* **Level 2 (Floating)**: Layered low-alpha shadow (`shadow-lg` / `shadow-[0px_4px_12px_-2px_rgba(0,0,0,0.06)]`) + 1px hairline. Used for dropdown menus, modal dialogs, command palettes (`<CommandPalette />`), and tooltips (`<TooltipWrapper />`).

**Forbidden**: Heavy dark drop shadows (e.g. `box-shadow: 0 15px 40px rgba(0,0,0,0.4)`), colorful glows, or exaggerated 3D card borders are **STRICTLY FORBIDDEN**.

### Text Inputs & Form Fields

* Header Row: Geist Mono font (`font-mono`), 12px (`text-xs`), uppercase (`uppercase tracking-wider`), text `#8f8f8f` (`var(--color-mute)`), background `#fafafa` (`var(--color-canvas)`), height 40px.
* Data Row: Geist Sans font (`font-sans`), 14px (`text-sm`), text `#171717`, border-bottom `1px solid #ebebeb`, row height 48px (dense) or 56px (standard), hover background `#fafafa`.
* Mobile Reflow: High-density tables MUST reflow into Touch Card View (`block sm:hidden`) on viewports ≤640px.

## 13. Dark Mode System

ReachInternational implements a dual-theme architecture (Light `#fafafa` canvas vs Dark `#0a0a0a` canvas).

```text
THEME PROPERTY           LIGHT THEME                      DARK THEME
──────────────────────────────────────────────────────────────────────────────────────────
Page Canvas           → #fafafa (var(--color-canvas))    #0a0a0a (var(--color-canvas))
Elevated Cards/Modals → #ffffff (var(--color-canvas-el)) #171717 (var(--color-canvas-el))
Primary Ink Text      → #171717 (var(--color-ink))       #fafafa (var(--color-ink))
Hairline Borders      → #ebebeb (var(--color-hairline))  #262626 (var(--color-hairline))
Secondary Body Text   → #4d4d4d (var(--color-body))      #a3a3a3 (var(--color-body))
Mute Subtitles        → #8f8f8f (var(--color-mute))      #737373 (var(--color-mute))
```

### Dark Mode Rules:
1. **Never Hardcode Single-Theme Colors**: AI agents MUST NOT use raw hex strings like `bg-[#fafafa]` or `text-[#171717]` in component templates. Use CSS variables (`bg-[var(--color-canvas)]`, `text-[var(--color-ink)]`) or Tailwind semantic color utilities so components auto-adapt to dark mode.
2. **Never Use Pure Black Text in Dark Mode**: Dark mode canvas sits at `#0a0a0a`, cards sit at `#171717`, text sits at `#fafafa`.

## 15. Forbidden Anti-Patterns (NEVER INTRODUCE)

AI agents MUST NEVER introduce any of the following visual design violations:

* ❌ **Arbitrary Hex Colors**: Hardcoding random color hexes like `#123456` or `#333333` when canonical tokens (`--color-ink`, `--color-body`, `--color-hairline`) exist.
* ❌ **Pure Black Body Text**: Setting body text in `#000000`. Body text MUST use `#4d4d4d` (`var(--color-body)`).
* ❌ **Mixing Button Radius Languages**: Placing rounded 100px marketing pills inside dense table row actions or app form rows.
* ❌ **Heavy Elevation Drop Shadows**: Adding `box-shadow: 0 20px 50px rgba(0,0,0,0.5)` to standard content cards.
* ❌ **Extra Decorative Gradients**: Adding background gradients to cards, tables, or navigation bars outside the hero section.
* ❌ **Custom Un-Tracked Display Headings**: Setting hero/h1 headings without tight negative letter-spacing (`tracking-tighter` / `-2.4px`).
* ❌ **Desktop-Only Data Tables**: Rendering data tables that clip or force horizontal page scrolling on mobile viewports without touch card reflow (`block sm:hidden`).
* ❌ **Nested Double Scrollbars**: Creating inner scroll containers within form bodies or card cards that produce double scrollbars.

## 16. Design Regression Protection Policy

Before making changes to any shared component in `apps/web/components/ui/` or `packages/design-tokens`:

1. **Audit All Downstream Consumers**: Inspect every page and module consuming the component across both `apps/web` and `apps/mobile`.
2. **Verify Theme Adaptation**: Verify that the component renders correctly in both Light Mode (`#fafafa` canvas) and Dark Mode (`#0a0a0a` canvas).
3. **Verify Viewport Reflow**: Verify that the component adapts smoothly across Mobile (≤640px), Tablet (641px–1023px), and Desktop (≥1024px) viewports.

## 17. AI Agent Pre-Implementation Checklist

Before writing any UI, HTML, CSS, or component code, every AI agent MUST complete this mental checklist:

* [ ] Have I inspected `DESIGN.md` for exact color tokens (`#171717`, `#fafafa`, `#ffffff`, `#ebebeb`), Geist fonts, border radii, and spacing scales?
* [ ] Am I using CSS variables (`var(--color-ink)`, `var(--color-canvas)`, `var(--color-hairline)`) instead of hardcoded hex values?
* [ ] Does my button implementation use the correct radius language (`6px` `rounded-sm` for app controls vs `100px` `rounded-full` for marketing pills)?
* [ ] Is display typography set in Geist Sans with tight negative tracking (`-2.4px` hero / `-1.28px` heading)?
* [ ] Are technical labels, machine codes, and column headers set in uppercase Geist Mono (`font-mono text-xs uppercase`)?
* [ ] Am I reusing canonical primitives from `apps/web/components/ui/` (`Button`, `Input`, `EnterpriseTable`, `SearchableSelect`, `TooltipWrapper`)?
* [ ] Have I included mobile touch card reflow (`block sm:hidden`) for data tables and touch targets ≥44px?

## 18. AI Agent Post-Implementation Design Audit

After completing code modifications, every AI agent MUST perform the following verification protocol:

1. **Visual Token Audit**: Verify zero un-tokenized hex colors or arbitrary pixel values were added.
2. **Theme Verification**: Verify components render cleanly in both Light and Dark modes.
3. **Responsive Viewport Audit**: Test layout behavior across Mobile (≤640px), Tablet (641px–1023px), and Desktop (≥1024px).
4. **Compilation Verification**: Run `pnpm typecheck` across all monorepo packages to ensure 0 TypeScript compilation errors.
5. **Memory Synchronization**: Update `AI/STATE.md`, `AI/CURRENT_TASK.md`, `AI/CHANGELOG_AI.md`, and `README.md`.
