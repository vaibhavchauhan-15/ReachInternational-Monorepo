# ReachInternational Production Design System Rules & Policy — `AI/RULES/DESIGN-SYSTEM.md`

> **AUTHORITATIVE DESIGN-SYSTEM ENFORCEMENT POLICY FOR AI AGENTS**  
> *This document establishes the binding visual design and UI component policy for all web (`apps/web`) and mobile (`apps/mobile`) development within the ReachInternational monorepo. Every AI coding agent MUST read, obey, and enforce these rules before creating or editing any user interface component, page layout, or styling code.*

---

## 1. Purpose

The purpose of this policy is to guarantee 100% visual and interactive consistency, prevent design fragmentation, protect brand identity, enforce responsive cross-platform layout standards, and eliminate arbitrary one-off UI implementations across ReachInternational.

AI agents MUST treat this document as an **executable design policy**. Any code generated by an AI agent that violates the visual specifications, color tokens, typography scales, border radii, or layout rules documented herein is considered defective and non-compliant.

---

## 2. Authoritative Source of Truth — `DESIGN.md`

The workspace root file:
```text
DESIGN.md
```
is the **PRIMARY AND AUTHORITATIVE SOURCE OF TRUTH FOR THE VISUAL DESIGN OF THE APPLICATION**.

### Core Authority Invariants:
1. **`DESIGN.md` Overrides Agent Preference**: AI agents MUST NOT invent custom visual styles, redesign components based on personal aesthetic taste, or introduce alternative design systems (e.g. default Tailwind blue/red, Material UI, Bootstrap, or arbitrary hex colors).
2. **`DESIGN.md` Overrides Accidental Implementation Deviations**: If an existing component in the codebase deviates from `DESIGN.md`, `DESIGN.md` remains authoritative. AI agents MUST NOT use non-compliant components as justification to propagate invalid design patterns.
3. **No Unintended Design Modifications**: AI agents MUST NOT alter global CSS variables in `apps/web/app/globals.css`, change tokens in `packages/design-tokens`, or edit `DESIGN.md` without explicit user instruction.

## 3. Design Philosophy — The Vercel Geist System

ReachInternational's visual identity is built on the **Vercel Geist System** — an intentional exercise in subtraction, creating a stark, high-density, black-on-near-white developer-and-enterprise platform aesthetic.

- **Ink & Canvas Foundation**: Near-black ink tone (`#171717`) set against a near-white background canvas (`#fafafa`) in light mode; stark dark mode (`#0a0a0a` canvas, `#171717` cards, `#fafafa` ink).
- **Near-Zero Chromatic Chrome**: Large surfaces MUST NOT be filled with bright chromatic colors. Color is strictly reserved for semantic status signals and the primary brand blue (`#0284c7` / `#0ea5e9`).
- **Crisp Hairline Surfaces**: 1px border (`#ebebeb` light / `#262626` dark) on white cards (`#ffffff`). Never heavy drop shadows.
- **Bimodal Border Radius Language**: Tight 6px square corners for app chrome and inputs vs. 64px for category pills and 100px for marketing CTAs.
- **Display Typography**: Geist Sans with tight negative letter-spacing (-2.4px on hero, -1.28px on section headings).
- **Technical Eyebrows**: Geist Mono uppercase section labels (12px, weight 500) for metadata and machine identifiers.

## 5. Typography Hierarchy Rules

The system operates strictly on **Geist Sans** and **Geist Mono**.

```text
TOKEN               FONT          SIZE   WEIGHT   LINE HEIGHT   TRACKING      USAGE
─────────────────────────────────────────────────────────────────────────────────────────────
display-xl          Geist Sans    48px   600      48px          -2.4px        Hero headline
heading-lg          Geist Sans    32px   600      40px          -1.28px       Section header
heading-md          Geist Sans    20px   600      28px          -0.4px        Card / modal title
label-sm            Geist Sans    14px   500      20px          -0.28px       Button / form label
mono-eyebrow        Geist Mono    12px   500      16px          0.5px (UPPER) Section label
body-lg             Geist Sans    16px   400      24px          0px           Lead prose
body-md             Geist Sans    14px   400      20px          0px           Default body
body-sm             Geist Sans    12px   400      16px          0px           Caption, metadata
code                Geist Mono    14px   400      20px          0px           Machine serials
```

### Mobile Typography Rules (`apps/mobile`):
- AI agents MUST use the canonical `<Text variant="...">` primitive or `useTypeStyle(variant)`.
- **Zero Raw Typography Properties**: Setting inline `fontSize`, `fontWeight`, `fontFamily`, `lineHeight`, `letterSpacing` on native style objects is **STRICTLY PROHIBITED** (enforced via `scripts/check-typography.mjs`).

## 6. Spacing Scale Rules (4px Base Unit)

- Spacing scale: `4px` (`xxs`), `8px` (`xs`), `12px` (`sm`), `16px` (`md`), `24px` (`lg`), `32px` (`xl`), `40px` (`2xl`), `64px` (`3xl`), `96px` (`4xl`), `128px` (`section`).
- Non-standard arbitrary pixel values (`11px`, `17px`, `23px`, `39px`) are **FORBIDDEN**.

---

## 7. Border Radius Rules

- **Operational Chrome**: Tight 6px square (`rounded-sm`) for inputs, selects, app action buttons, and dropdown items.
- **Card Surfaces**: 12px (`rounded-md`) for operational cards and form containers.
- **Modal Dialogs**: 16px (`rounded-lg`) for large dialogs and mobile sheets.
- **Category Filter Tabs**: 64px (`rounded-full` / `rounded-[64px]`) for `SegmentedToggle`.
- **Marketing CTAs**: 100px (`rounded-full`) for hero marketing pills.
- **Avatars & Status Dots**: 9999px (`rounded-full`).

---

## 8. 3-Tier Responsive Viewport Protocol

Every page and component must be responsive across:
- **Mobile (≤ 640px)**: Data tables reflow into touch cards (`block sm:hidden`), horizontal scroll filter strips (`overflow-x-auto`), bottom sheet modals, minimum 44px touch targets.
- **Tablet (641px–1023px)**: 2-column grid reflow (`grid-cols-2`), fluid modal panels (`sm:max-w-xl`), responsive header toolbars.
- **Desktop (≥ 1024px)**: Full multi-column dashboard layouts, high-density enterprise tables (`hidden sm:block`), fixed collapsible sidebar.

---

## 9. Web & Native Parity Rule

Whenever ANY UI component, screen, or style is modified in Web, the agent MUST apply the exact same visual design, colors, font hierarchy, and interaction flow in Native Mobile. Web and Native MUST NEVER drift out of sync.
